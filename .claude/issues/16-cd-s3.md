## Summary

Private / customer plugins not published on WP.org are distributed via an S3 bucket the customer can read. `cd-s3.yml` uploads the release artifact to a configured S3 path — a versioned object (`<prefix><tag>.zip`) plus a rolling `<prefix>latest.zip` — and optionally invalidates a CloudFront distribution so the new `latest.zip` is served immediately. It is the third CD workflow (with `cd-github-release.yml` and `cd-wp-org.yml`) and the S3 target the CD orchestrator (`wp-cd.yml`, #17) will call.

## Decisions made

- [2026-05-29] **No blocker — proceeded.** `aws-actions/configure-aws-credentials@v6.1.3` is official and SHA-pinnable; the AWS CLI is preinstalled on `ubuntu-latest`. The issue's "depends on #11" is a *logical/runtime* dependency: the workflow only downloads an artifact by name (the producer `ci-build.yml` is merged), with no code-level `uses:` on `ci-test-build-artifact`. Secrets declare via `workflow_call`; no checkout needed; no private cross-repo dependency.
- [2026-05-29] **Versioned object keyed by `tag`** (chosen with the user): `s3://<bucket>/<prefix><tag>.zip` + an always-overwritten `<prefix>latest.zip`. Predictable URL; uses the required `tag` input. Supersedes the issue's `<artifact-filename>` key, which left `tag` unused.
- [2026-05-29] **`aws-actions/configure-aws-credentials@99214aa6889fcddfa57764031d71add364327e59 # v6.1.3`, SHA-pinned** (latest stable; static access keys via inputs still supported). The issue's "v4.x" was illustrative.
- [2026-05-29] **Static access-key auth** via the two required secrets (per the issue), not OIDC.
- [2026-05-29] **Injection-safe:** `tag` / `bucket` / `prefix` / `cloudfront-distribution-id` pass through step `env:` and are referenced as `$VARS`; nothing interpolated as `${{ inputs.* }}` inside a shell script (the issue's reference inlined them — a shell-injection risk). Matches `cd-github-release` / `cd-wp-org`.
- [2026-05-29] **No checkout; `permissions: contents: read`.** The job only downloads an artifact and talks to AWS; `download-artifact@v4` is same-run and independent of `GITHUB_TOKEN` scopes.
- [2026-05-29] **Single `.zip` enforced:** fail with `::error::` if the artifact contains zero or more than one `.zip`, so a misconfigured `artifact-path` can never deploy the wrong bundle.
- [2026-05-29] **Branched off `release/v1.0.0`**; PR targets `release/v1.0.0`.

Local logic test (aws stubbed on PATH, run under bash, all pass):
- single zip, `prefix=plugins/acme/`, `tag=v1.2.3` → `aws s3 cp ... s3://my-bucket/plugins/acme/v1.2.3.zip` and `.../latest.zip`.

- CloudFront path: `/plugins/acme/*` (prefix set) and `/*` (empty prefix).
